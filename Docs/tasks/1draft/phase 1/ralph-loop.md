## Phase 1 Definition of Done (from §16.1)

- Tasks stored under `PATIENT#<uid>` (UID-first)
- Existing MRN routes still work (resolve to UID via `ids.mjs`)
- Creating a task emits: task current state, `TASK_UPDATE` event, patient `TASKSYNC` master event
- Updates use `clientMutationId` idempotency + `expectedVersion` optimistic concurrency
- Task update history fetchable per task
- Task copy text generated by backend (human + agent formats)
- Proposal create / edit / commit / reject works; committed proposal links to final task/update
- Task sync query after checkpoint works
- Doctor-only `TASKSYNC#DOCTOR#<doctorId>` stream works
- **Plus (from revised scope):** recurrence definitions CRUD + runner endpoint (`POST /tasks/recurrences/run?date=...`) generates daily TASK occurrences

**Fix A — Timeline integration (concern #2):**

- Net result: `GET /patients/:id/timeline` now returns both episode rows and task-event rows interleaved by timestamp, with `kind` discriminator for the UI.

**Fix B — Directory APIs (concern #3):**

- New file `tasks/directory.mjs` with `listPatients({department, q, limit})` and `listStaff({department, role, q, limit})`. Both return thin picker-shaped DTOs (id + display label + ward/bed for patients; role + email for staff). Uses existing `DEPT_INDEX` GSI when `department` is set; pragmatic Scan + post-filter as fallback (acceptable for picker scale; flagged for future dedicated GSI).
- `tasks/index.mjs`: mounted `GET /directory/patients` and `GET /directory/staff`. Plumbed `INDEX` through `deps` (was missing before; now passed for these and any future GSI-using helpers).

**Fix C — Status filter pushed into DDB (concern #4):**

- `tasks/task_store.mjs::listTasksByPatient`: accepts `{ status }`; when present, sets `FilterExpression: "#s = :status"`. Still scans the partition (same RCU) but drops non-matching items before they hit the wire. Comment in code points at the long-term answer (composite SK or per-patient status GSI).
- `tasks/task_crud.mjs::listTasks`: passes status straight through, drops the in-memory `.filter(...)`.

**Fix D — Idempotency replay returns the real task (concern #5):**

- `tasks/task_crud.mjs::createTask` and `patchTask`: on idempotency hit, the marker stored only `{ task_id }`. Old code returned `prior.response_summary?.task` which was always undefined. New code re-fetches the task via `getTask(ddb, TABLE, uid, priorTaskId)` and returns the authoritative current item. Cheaper to store (small marker) + always fresh on replay.
- `mountTaskRoutesV2` route handlers in `index.mjs` already pass `out.item` through `toTypedTask()`, which is null-safe — so a replayed marker for a since-deleted task degrades to `{ task: null, idempotent: true }` instead of crashing.

**Fix E — Proposal reject bug (concern #6):**

- `tasks/task_proposals.mjs::rejectProposal`: removed the broken first `UpdateCommand` (it referenced `:c` in `ConditionExpression` without binding it). Single clean call with `ConditionExpression: "attribute_exists(PK) AND #s <> :committed"` and proper binding. On `ConditionalCheckFailedException`, the code now distinguishes "not found" (404) from "already committed" (400) by re-fetching and inspecting status. No more silent fallthrough.
